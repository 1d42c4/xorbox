# File formats (version 1)

## Raw XOR

There is no header or tag. Byte `i` is input byte `i` XOR key byte `i`. With explicit
`--repeat-key`, key indexing is `i mod key_length`. Both byte positions start at 0
on each invocation. Normal mode refuses short keys; both modes reject an empty key.
An empty input is allowed with a nonempty key. Output length equals input length.

## key.meta

UTF-8 JSON with unknown/duplicate fields rejected, at most 16 KiB. All listed
fields are required. Fixed settings are validated exactly, including at restore.

| Field | Value |
| --- | --- |
| format | `xorbox-key` |
| version | integer 1 |
| bytes | integer 1..20,000,000,000 |
| kdf | `argon2id-v19` |
| memory_kib | integer 65536 |
| passes | integer 3 |
| lanes | integer 4 |
| salt_hex | 16 random bytes, 32 hex characters |
| generator | `chacha20-ietf-counter0` |
| nonce_hex | 12 random bytes, 24 hex characters |
| key_sha3_512 | SHA3-512 of generated key bytes, 128 hex characters |

Password encoding: exact UTF-8, terminal-entered line ending excluded. No Unicode
normalization. Derive a 32-byte seed with Argon2id version 0x13 and the listed
parameters; no associated data or Argon2 secret parameter. Initialize IETF ChaCha20
with that seed, nonce, and block counter 0. Output exactly `bytes` keystream bytes.
All integers internal to ChaCha follow its standard little-endian definition.

The metadata digest detects a wrong restored key, but is not a signature or MAC on
the metadata and is not an authentication tag for XOR ciphertext. Keep a trusted
metadata backup. It also provides an offline password-verification target.

## XChaCha file

Uses the libsodium-compatible **XChaCha20-Poly1305 secretstream** construction,
implemented by Dryoc. This is an application container around secretstream; it is
not a single-message raw XChaCha20-Poly1305 AEAD blob.

Header (36 bytes):

1. Eight bytes: ASCII `XORBOX`, then `00 01` (magic and format version).
2. Four bytes: little-endian u32 chunk size, exactly 1,048,576.
3. Twenty-four bytes: the fresh random secretstream header generated by init_push.

Each record is a four-byte little-endian u32 ciphertext length, followed by that
many secretstream ciphertext bytes. Length is bounded to 17..1,048,593 before
allocation/read. The complete 36-byte header is associated data for **every** record.
Secretstream handles record ordering and internal rekeying.

Data records carry tag MESSAGE (0) and 1..1,048,576 plaintext bytes. All except the
last data record must be full-sized. An empty plaintext file has no data records.
There is always a separate, empty FINAL (3) record with exactly 17 ciphertext bytes.
No bytes may follow it. Other tags, empty data records, multiple short data records,
oversized records, an absent final record, and trailing bytes are rejected.

For plaintext length L and C=1,048,576, ciphertext length is
`36 + L + 21 * ceil(L/C) + 21`; the last 21 bytes are the mandatory final record.
The key is exactly 32 raw bytes from `xcha.key` and is never included in the file.

Independent interoperability tests in `verification/interop.py` use PyNaCl's actual
libsodium implementation in both directions. The magic, framing, and associated
data must still be handled by any other reader/writer.
